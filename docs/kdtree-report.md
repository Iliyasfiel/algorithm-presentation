## 02｜背景：为什么不能每次扫描全部点？

**建议用时：1 分钟。对应要求：问题背景及来源。**

### 页面内容

场景：机器人或扫描设备获得三维采样点，需要反复完成两类任务：

1. **范围查询**：找出给定长方体内的全部点，或只统计点数。
2. **最近邻查询**：找出距离指定位置最近的采样点。

暴力方法每次检查全部 N 个点；逐维计算的最坏成本为 O(dN)，固定维度时为 O(N)。反复查询时，希望用预处理和额外存储换取更少的访问。

### 讲解备注

范围查询对应点云裁剪、空间区域筛选；最近邻查询对应点云处理中的邻域搜索。算法不是消除所有最坏情况，而是利用空间结构跳过无需检查的数据。

三维是为了展示方便。二维和更高维也可以使用范围树等结构；不要宣称“只有 KD-tree 能处理三维”或“KD-tree 在所有指标上都优于树套树”。本次关注的是空间存储相对节省，以及对范围查询和距离查询的统一支持。

### 讲解备注

## 05｜Python 实现与一般维度的建树分析

**建议用时：1 分钟。对应要求：实现与算法分析。**

### 页面内容

节点字段：`id, point, axis, left, right, size, bbox`。

```python
def build(points, depth=0):
    if not points:
        return None
    axis = depth % d
    ordered = sorted(points, key=lambda p: (p.coords[axis], p.id))
    mid = len(ordered) // 2
    left = build(ordered[:mid], depth + 1)
    right = build(ordered[mid + 1:], depth + 1)
    return make_node(ordered[mid], axis, left, right)
```

上面是接口示意；`d` 由外层统一传入或封装保存，`make_node` 负责合并大小和包围盒。

固定 d，递归排序版本：

\[
B(N)=2B(N/2)+O(N\log N)=O(N\log^2N).
\]

中间步骤：第 ℓ 层有约 2^ℓ 个子问题，每个规模 N/2^ℓ，因此该层排序工作为 O(N(log₂N−ℓ))。令 L=⌈log₂N⌉，累加各层：

\[
O\left(N\sum_{\ell=0}^{L-1}(L-\ell)\right)
=O\left(N\frac{L(L+1)}2\right)=O(N\log^2N).
\]

线性时间中位数选择与划分版本：

\[
B(N)=2B(N/2)+O(N)=O(N\log N).
\]

此时每层所有子问题的选择与划分成本合计 O(N)，共有 O(log N) 层。包围盒在自底向上合并时每个节点付出 O(d)，共 O(dN)，单独加到相应建树成本中。

### 讲解备注

递推忽略每个内部节点取走一个点的常数差异，不影响渐近结果。第二种是理论优化版本，不代表 Python 的 `sorted` 已经达到该界。

若显式保留维度成本，两种版本分别为 O(N log²N + dN) 和 O(N log N + dN)，其中 dN 包含输入坐标处理及自底向上包围盒合并；假定单次坐标比较为 O(1)。随机选择算法通常提供期望线性选择时间；若声称最坏建树界，需要使用有最坏线性保证的选择方法。

节点和包围盒的持久存储为 O(dN)，固定 d 时为 O(N)；不把 Python 临时列表开销混称为节点存储。此平衡树高度为 O(log N)。

## 06｜范围查询：三种空间关系

**建议用时：1 分钟。对应要求：算法思想及实现。**

### 页面内容

一般 d 维轴对齐查询盒：

\[
Q=\prod_{i=1}^{d}[a_i,b_i].
\]

设 B 是当前子树的包围盒：

| 关系 | 范围报告 | 范围计数 |
|---|---|---|
| B 与 Q 不相交 | 跳过 | 返回 0 |
| B 完全包含于 Q | 收集整棵子树的点 | 返回 `size` |
| 部分相交 | 检查本节点，再递归孩子 | 检查本节点，再递归孩子 |

### 讲解备注

“整棵接收”不是说报告所有点只需 O(1)：报告仍需遍历并输出这些点；计数才可以直接读 `size`。

轴对齐范围查询不同于球形半径查询。本次 O_d(N^(1−1/d)+r) 的分析针对轴对齐盒，不能不加证明地套到球形查询。

### Python 演示约定

- `range_report(root, lower, upper, trace=None) -> list[Point]`。
- `range_count(root, lower, upper, trace=None) -> int`。
- 区间采用闭区间，落在边界上的点计入结果。
- 盒相交、包含和点包含判定均按 d 个维度执行。
- 核心报告函数按树的遍历顺序返回，不按 ID 排序，以保持 O(r) 输出成本。只在正确性比较和 JSON 展示结果导出时排序 ID，这部分不计入核心查询性能。

### 页面代码：范围报告

以下代码从 `demo/teaching.py` 提取，PPT 构建时使用同一份源码。几何辅助函数复用 `demo/kdtree.py`；演示片段省略输入校验与事件记录。

```python
def report(node, lo, hi, out):
    if node is None:
        return
    state = relation(node, lo, hi)
    if state == "disjoint":
        return
    if state == "contained":
        out.extend(subtree_points(node))
        return
    if inside(node.point, lo, hi):
        out.append(node.point)
    report(node.left, lo, hi, out)
    report(node.right, lo, hi, out)
```

## 08｜范围计数与正确性

**建议用时：0.75 分钟。对应要求：正确性分析。**

### 页面内容

不变式：每个子树的全部点都在它维护的包围盒中。

1. **不相交**：子树没有任何点可以落入查询盒，剪枝不漏解。
2. **完全包含**：子树全部点均为答案，整棵接收不引入错误。
3. **部分相交**：检查本节点，并递归处理两棵子树，覆盖全部剩余可能。

对树结构归纳，可得返回结果无遗漏、无多余点；每个节点的数据仅输出一次。

### 讲解备注

一般 d 维的正确性只依赖集合包含与相交关系，不依赖三维图。计数正确性额外依赖 `size` 的维护正确。插入和重建后必须重新合并包围盒、更新大小，否则正确的查询逻辑也可能得到错误答案。

### 页面代码：范围计数

以下代码从 `demo/teaching.py` 提取，PPT 构建时使用同一份源码。几何辅助函数复用 `demo/kdtree.py`；演示片段省略输入校验与事件记录。

```python
def count(node, lo, hi):
    if node is None:
        return 0
    state = relation(node, lo, hi)
    if state == "disjoint":
        return 0
    if state == "contained":
        return node.size
    hit = int(inside(node.point, lo, hi))
    return (hit + count(node.left, lo, hi)
                + count(node.right, lo, hi))
```

## 09｜一般 d 维：范围查询复杂度的来源

**建议用时：2 分钟。对应要求：重点复杂度推导。**

### 页面内容

前提：固定 d≥2，静态中位数平衡 KD-tree，循环选轴，轴对齐盒查询。先采用一般位置假设，避开切分面与查询边界重合的退化情况；实现中的闭区间和重复坐标仍需独立处理。

考虑查询盒的一张边界超平面。经过一轮 d 层划分：

- 子问题规模缩小到约 N/2^d。
- 与边界法向相同的维度，只需跟进一侧。
- 其余 d−1 个维度最多各跟进两侧。
- 因而最多穿过 2^(d−1) 个子区域。

边界穿越的访问量满足：

\[
T_d(N)\le 2^{d-1}T_d(N/2^d)+O_d(1).
\]

\[
\log_{2^d}2^{d-1}=\frac{d-1}{d}
\quad\Longrightarrow\quad
T_d(N)=O_d(N^{1-1/d}).
\]

不直接使用主定理跳到结论，令 a=2^(d−1)、b=2^d，将递推展开 j 轮：

\[
T_d(N)\le a^jT_d(N/b^j)+C_d\sum_{i=0}^{j-1}a^i.
\]

取 L≈log_bN，使叶子规模变为常数。固定 d≥2 时 a>1，因此几何级数为 (a^L−1)/(a−1)=O_d(a^L)，叶子项也为 O_d(a^L)。于是：

\[
T_d(N)=O_d(a^L)
=O_d\left(N^{\log_b a}\right)
=O_d\left(N^{(d-1)/d}\right).
\]

推导可以先假设 N 是 2^d 的整数次幂以便展示；取整及中位数取走一个点不改变渐近上界。三维代入 a=4、b=8，得到指数 log₈4=2/3。

### 讲解备注

一轮展开的常数操作数可以依赖 d，所以写 O_d(1)。查询盒有 2d 个面，固定 d 时只引入依赖 d 的常数。跨越边界的区域需要展开，完全包含区域作为整棵子树接收；其遍历边界上的额外工作也可计入边界访问量。

证明使用经典划分区域。代码用更紧的包围盒，可以更早排除或接收子树，不会比采用相同遍历规则的划分区域方法更晚停止。但树结构必须符合分析前提，不能把任意选轴、任意动态平衡树都套用这一证明。

重复坐标可使用一致的平局规则保证构建终止；若要覆盖全部退化几何情况的严格理论保证，还需要明确符号扰动或等价边界约定。本次把一般位置下的经典结论作为正文证明范围。

### 画面与演示

主画面以 d 维计数式呈现推导，旁边用三维截面辅助解释“一轮 3 层中最多穿过 4 个子区域”。不要只展示三维递推再直接宣称一般维度结论。

## 10｜范围报告、计数与维度效应

**建议用时：1 分钟。对应要求：复杂度结论及适用范围。**

### 页面内容

在第 09 页条件下：

\[
\boxed{\text{范围报告： }O_d(N^{1-1/d}+r)}
\]

\[
\boxed{\text{范围计数： }O_d(N^{1-1/d})}
\]

| 维度 | 范围报告 | 范围计数 |
|---|---|---|
| d=2 | O(√N+r) | O(√N) |
| d=3 | O(N^(2/3)+r) | O(N^(2/3)) |
| 一般固定 d≥2 | O_d(N^(1−1/d)+r) | O_d(N^(1−1/d)) |

### 讲解备注

报告必须支付输出成本 Ω(r)。计数在完全包含时直接读子树大小，所以无需逐点输出。这种查询界也称输出敏感界，因为成本包含实际答案规模。

单独处理 d=1：可用平衡有序树完成区间报告 O(log N+r)，维护子树大小后计数 O(log N)。不能把 d=1 代入前页的退化递推后得到常数查询。

原因是 d=1 时 a=1，展开式中的和变成 L，而不是 a>1 时由最后一项主导的几何增长；因此保留 O(log N) 项。对 d≥2 的报告查询，边界访问与停止展开的完整包含子树分开计费：几何判断由边界项控制，收集所有结果的工作量共 O(r)；计数直接读取 size，去掉输出项。

随着 d 增长，指数 1−1/d 趋近 1，且隐藏常数与逐维操作成本也会变化；该结论不承诺高维仍然高效。静态经典范围查询结论参考 [1]。

## 11｜最近邻：用距离下界决定是否回溯

**建议用时：1.5 分钟。对应要求：算法思想、正确性及实例。**

### 页面内容

对一般 d 维查询点 q、包围盒 B=∏[l_i,u_i]：

\[
\delta_i=\max(l_i-q_i,0,q_i-u_i),
\qquad
\operatorname{dist}_{\min}^2(q,B)=\sum_{i=1}^{d}\delta_i^2.
\]

- 维护当前最小距离平方 best²。
- 优先访问包围盒距离下界较小的子树。
- 若子树距离下界大于 best²，整棵剪枝。
- 否则继续搜索，并更新当前最近点。

三维例子：q=(6,3,3)，最近点为 B=(5,4,2)，距离平方为 3。

### 讲解备注

正确性：包围盒内任意点距离均不小于该下界；下界已经大于候选距离时，子树不可能改进答案。

用距离平方比较，避免重复开方。若相同距离时要求选择最小 ID，需要保留等距改进的可能性，因此统一采用“下界严格大于 best² 才剪枝”。候选按 `(距离平方, ID)` 比较。

三维画面可显示搜索球和包围盒，但公式与证明适用于一般维度。精确最近邻最坏访问全部点，朴素逐维实现为 O(dN)，固定 d 时为 O(N)。树高 O(log N) 不意味着最近邻查询最坏 O(log N)。

### Python 演示约定

`nearest(root, query, trace=None) -> (Point, distance_squared)`。空树返回值由实现明确规定。输出 `visit, update_best, prune_distance` 事件；与暴力结果比较最小距离和约定的 ID。

## 12｜最近邻代码与静态查询成本

**建议用时：0.75 分钟。对应要求：算法分析与性质。**

### 页面内容

| 项目 | 一般维度下的结论与条件 |
|---|---|
| 建树，递归排序 | O(N log²N + dN)；固定 d 时 O(N log²N) |
| 建树，线性中位数选择 | O(N log N + dN)，需相应选择算法保证 |
| 持久存储 | O(dN)，含坐标及包围盒 |
| 平衡树高 | O(log N) |
| 正交范围报告 | 经典静态条件下 O_d(N^(1−1/d)+r)，d≥2 |
| 正交范围计数 | 同上，维护 size 时 O_d(N^(1−1/d)) |
| 精确最近邻 | 最坏 O(dN)；固定 d 时 O(N) |

优势：空间存储相对节省；支持多种空间查询；在适宜的低维数据上可减少访问。

局限：高维剪枝可能变弱；动态更新需要维护；数据分布会影响实际访问量。

### 讲解备注

复杂度是不同算法及条件下的结论，不是同一个实现同时自动具备的全部保证。工程耗时还受 Python 对象、递归、包围盒判断、输入规模和查询分布影响。不要宣称 KD-tree 对所有数据都快于向量化暴力计算。

### 页面代码：最近邻

以下代码从 `demo/teaching.py` 提取，PPT 构建时使用同一份源码。几何辅助函数复用 `demo/kdtree.py`；演示片段省略输入校验与事件记录。

```python
def nearest(root, q):
    best = (inf, "", None)  # 距离平方、ID、点
    def visit(node):
        nonlocal best
        if node is None or lower_bound(q, node) > best[0]:
            return
        best = min(best, (distance2(q, node.point),
                          node.id, node.point))
        children = [n for n in (node.left, node.right) if n]
        children.sort(key=lambda n: (lower_bound(q, n), n.id))
        for child in children:
            visit(child)
    visit(root)
    return best[2], best[0]
```

## 14｜借鉴替罪羊树：失衡子树局部重建

**建议用时：1.25 分钟。对应要求：动态维护拓展。**

### 页面内容

维护子树大小，取固定阈值 α∈(1/2,1)，例如 α=0.75：

α 是**最大孩子占比阈值**：要求较大孩子的节点数不超过整棵子树节点数的 α 倍。分母 size(u) 包含当前节点 u 自身，不能改成 size(L)+size(R)；该比例衡量点数，不衡量空间体积。

\[
\max(\operatorname{size}(L),\operatorname{size}(R))
>\alpha\operatorname{size}(u).
\]

α=0.75 表示允许任一孩子最多占整棵子树的 75%。例如当前 size(u)=12，左右孩子大小分别为 9 和 2，则 9/12=0.75，因判定是严格大于而不触发。再向大孩子插入一点后，整树大小 13、较大孩子 10，10/13≈0.769>0.75，触发重建。

选择范围 1/2<α<1 的原因：中位数重建后任一孩子至多约占一半，α>1/2 为后续插入留出余量，并保证第 15 页的 2α−1 为正；α<1 则保证沿路径的子树规模按固定比例收缩。α 越小，允许的偏斜越少，通常重建更积极、树高更低；α 越接近 1，约束越宽松，可能减少重建，但路径更长。这里 α 为不随 N 变化的常数，O_α 隐藏的常数允许依赖它；不是 α 越大或越小就全面更优。

触发后：

1. 收集失衡子树全部点。
2. 从该子树根的原有深度开始，重新循环选轴。
3. 按中位数递归建树。
4. 接回原树，更新祖先大小和包围盒。

### 讲解备注

这里借鉴的是替罪羊树的局部重建思想，不声称实现与经典 ScapegoatTree 完全一致。经典替罪羊树的背景参考 [2]。

为使代码策略明确：一次插入后，在插入路径上选择**最靠近根的失衡节点**，只重建该子树一次；如果没有失衡节点则不重建。重建后的子树内部按中位数平衡，祖先左右节点数不因重建改变。可通过“记录路径、更新、选取节点、重接”实现。

普通搜索树的旋转依赖单一全序；KD-tree 节点还承担不同维度的空间约束，不能直接套用普通 AVL/红黑树旋转。重建可以重新建立这些约束。

### 画面与演示

突出失衡子树，展示“收集点 → 平衡重建 → 接回”的三步图。标注重建前后节点数不变、树高改变、包围盒必须重新计算。

## 15｜重建成本、树高与摊还分析

**建议用时：1 分钟。对应要求：拓展复杂度分析。**

### 页面内容

设重建子树有 m 个点：

| 工作 | 成本 |
|---|---|
| 收集点引用 | O(m) |
| 递归排序重建 | O(m log²m + dm) |
| 线性中位数选择重建 | O(m log m + dm) |
| 不发生重建的一次插入 | O(dh)，含沿途包围盒维护 |

核心取舍：用偶发的较大重建成本，换取后续更短的路径。

### 讲解备注

当每个节点都满足固定 α 的子树大小约束时，每下降一层，子树规模至多乘 α，因此树高为 O(log N)。这是树高保证，不是所有空间查询的访问量保证。

更具体地，下降 k 条边后节点规模至多 α^kN，而非空节点至少包含 1 点，所以 1≤α^kN，得到 k≤log_(1/α)N。若树高按节点数计，则 h=k+1，仍为 O(log N)。未重建插入在 h 个路径节点上各付出 O(d) 的比较和元数据维护成本，得到 O(dh)；根级重建则令 m=N，单次更新不能再由路径长度单独定价。

演示实现仅在整树根维护一个 ID 集合，用于检查重复 ID，空间为 O(N)，不会为每棵子树复制 ID 集合。哈希集合的成员检查为平均 O(1)、插入为摊还平均 O(1)；上表 O(dh) 是路径比较与元数据维护成本。手工构造且没有注册表的根首次插入时需额外初始化一次 ID 集合。

一次插入可能触发根级重建，不能声称每次更新最坏 O(log N)。当前递归排序版本的单次更新最坏上界为 O(N log²N+dN)，因为重建规模可达到 N。普通替罪羊树可在线性时间重建有序子树，而 KD-tree 要重新进行多维划分，不能直接照搬其 O(log N) 摊还更新结论。下面针对本次策略单独推导保守上界；这是本汇报的计费分析，不是参考资料 [2] 对 KD-tree 的直接结论。

### 摊还分析的前提

- 从空树开始，只考虑成功插入唯一 ID 的点；不讨论删除。
- α 是固定在 (1/2,1) 内的常数；每次选择路径上最靠近根的失衡子树重建。
- 新建与重建均采用按中位数平分点数的循环选轴建树。
- N 表示整个序列中的最大点数；哈希操作按平均/摊还平均 O(1) 计。
- 关闭 trace、元数据全树校验和序列快照，分析核心数据结构操作。

### 第一步：更新后恢复 α 约束

一次插入只会改变搜索路径上的节点大小。路径外仍然平衡；最高失衡节点的祖先未失衡，重建不改变该子树的点数，因此也不改变祖先两侧大小。重建子树内部按中位数构建，均满足 α 约束。故更新结束后整树满足约束，插入路径只有 O_α(log N) 个节点。

### 第二步：下一次重建需要累积多少插入？

考虑一个节点从最近一次自身或祖先重建之后，到它下一次触发重建之前的生命周期。初始子树规模为 s，任一孩子规模不超过 s/2。之后向这棵子树新增 t 个点，现有规模 m=s+t。即使 t 个点全进入同一孩子，大孩子仍至多 s/2+t。

\[
\alpha m<\max(|L|,|R|)\le s/2+t
=m/2+t/2
\quad\Longrightarrow\quad
t>(2\alpha-1)m=\Omega_\alpha(m).
\]

后代的局部重建不改变该节点左右子树的点数，因此不影响不等式。祖先重建会结束当前节点生命周期，产生新的中位数子树；其信用账户从零重新开始。

### 第三步：用路径信用支付重建

设当前版本重建费用 C(m)=O(m(log²m+d))。在每次插入经过的每个节点账户中分别存入 O_α(log²N+d) 信用，包括未来候选节点自身；这些存款分别计入本次插入的摊还费用。

下一次规模 m 的重建之前，有 Ω_α(m) 次插入经过该节点，所以累计信用足以支付 C(m)。信用绑定 Node 实例，不绑定 Point 或点 ID：后代重建不清空存活祖先的账户；候选子树重建只花候选根的账户，随后旧子树全部节点及其未用账户作废。新建节点从零存款，不能沿相同点 ID 继承旧信用。祖先重建时丢弃后代剩余信用只会浪费存款，不会造成同一笔信用重复支付。

每次插入经过 O_α(log N) 个祖先，故包括路径维护在内的保守摊还上界为：

\[
\boxed{O_\alpha(\log^3N+d\log N)}.
\]

若中位数选择版本可保证 C(m)=O(m(log m+d))，改为每祖先每次存 O_α(log N+d)，同理得到：

\[
\boxed{O_\alpha(\log^2N+d\log N)}.
\]

因此纯插入 N 个点的核心总成本上界，分别为 O_α(N(log³N+d log N)) 和 O_α(N(log²N+d log N))。这是保守上界，不声称是紧界。固定 d 后，分别可简写为 O_α(log³N) 和 O_α(log²N) 的每次摊还成本。

### 空间与演示开销

核心结构持久空间仍为 O(dN)，根 ID 集合增加 O(N)；一次重建同时保留旧子树、新子树及 O(m) 个临时点引用，不改变 O(dN) 峰值空间阶数，平衡递归栈为 O(log N)。记录整段插入序列的全部树快照则可能使用 O(dN²) 空间，这属于离线演示数据，不包含在核心空间和摊还界中。trace 中收集或排序子树 ID 的费用也必须单独计入；实验计时使用关闭追踪的独立树。

同样，仅恢复 α 平衡，不足以直接沿用第 09 页每轮 d 层的中位数递推。动态树可以继续正确查询，但其范围查询复杂度需要单独论证。实验中的访问量改善不替代理论保证。

## 18｜总结、答问与参考资料

**建议用时：0.5 分钟，答问另计。对应要求：总结及资料来源。**

### 页面内容

1. **结构**：循环选轴与中位数划分，把多维点组织成空间层次。
2. **查询**：范围查询利用包含关系，最近邻利用距离下界。
3. **分析**：一般固定 d≥2 的经典静态范围报告界为 O_d(N^(1−1/d)+r)，三维为 O(N^(2/3)+r)。
4. **维护**：局部重建恢复树高平衡；在纯插入等条件下，递归排序版本的保守摊还更新界为 O_α(log³N+d log N)，动态查询界仍需另外分析。

### 备用答问备注

- 为什么不只走到一个叶子？其他子树可能仍含更优答案，必须用下界排除。
- 报告和计数为什么不同？报告有 Ω(r) 输出成本，计数可以直接利用 size。
- 平衡后是否所有查询都是 O(log N)？不是，树高与总访问节点数不同。
- 为什么证明用一般维度，画图却用三维？三维只是可视化实例，公式与正确性不依赖三维。
- 重建是否保持旧划分轴？从原深度开始重建，保持与祖先循环选轴约定一致。
- 同坐标的点怎么办？以唯一 ID 打破排序平局，查询仍按真实坐标判断；理论退化边界需明确约定。
- 本次暂不扩展：删除、惰性删除、k 近邻完整实现、近似查询及动态范围查询的严格理论界。
